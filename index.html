核心結論（依目前已上傳的 WO 比對報告即時計算）

    最終可行性報告（任務 9）

    數字會隨資料更新自動重新計算，非寫死的截圖數字。

    一、專案背景與目標

    GEM、Facemask 兩條產線的 MES(生產紀錄)與 Actual Cost(成本系統)原本各自獨立，員工需要在兩套系統重複輸入相同的生產數量。專案目標：確認兩系統之間是否存在重複輸入問題，並評估建立單一輸入平台、讓員工只需輸入一次的可行性。

    二、關鍵發現

    1. 料號可作為串接鍵（任務 4）

    2. 逐筆比對＋對照生產計畫（任務 5，最具決定性的證據）


    結論：落差主要來自 MES 端漏記／採用率不足，不是 Actual Cost 重複輸入。

    3. 登錄方式（任務 7，已確認）
    Actual Cost 的生產數量登錄，人工鍵入與 Excel 匯入兩種方式都在用，並非單一管道。

    4. 單位換算（任務 6）

    5. 設備對應顆粒度發現（過程中新發現，原始任務清單沒有）
    Facemask 的 IOT 設備（ENC／F-FCE 系列）並非「一台設備＝一個固定工序」——同一台設備生產不同料號時，Master 登記的工序代碼會不同（如 Autotie、Autogar、GT001 等），且大部分工序（裁切、包裝等）根本是純人工站別，天生沒有 IOT／MES 資料。這代表 Facemask 的資料結構複雜度遠高於 GEM，MES 覆蓋率先天受限。

    三、尚未解決事項

    任務 3：MES 是否有員工／站別層級匯出功能——已確認目前的匯出檔沒有，但尚未問過 MES 系統管理員做最終核實。

    任務 8：Actual Cost 系統負責窗口尚未確認，不知道後續整合要找誰接洽。

    四、可行性結論

    1. 是否存在重複輸入問題？部分存在，但情況比原先假設更複雜。
    兩系統確實會記錄同一批生產數量，但不能簡單認定為「Actual Cost 在做多餘的工作」——MES 端的自動採集（IOT）覆蓋率本身不完整，尤其 Facemask 絕大部分工序仍是純人工站別，天生沒有 MES 資料可用；在 MES 沒有覆蓋到的地方，Actual Cost 的人工登錄反而是唯一可靠的資料來源。

    2. 單一輸入平台目前不建議整體全面推動，但可分階段局部整合：

    ・第一階段（可立即做）：針對 GEM 部門，以及 Facemask 中已有 IOT 且設備對應驗證過的工序，MES 資料已可信，可考慮讓 Actual Cost 直接引用 MES 產出數量，員工不必重複鍵入。 ・第二階段（需要前置投資）：若要擴大到更多工序，需先增設 IOT 感測器、或補齊人工站別的產量回報機制，才能讓 MES 覆蓋率提升到值得整合的程度。 ・手工站別（尤其 Facemask 多數工序）：短期內仍須保留人工／Excel 登錄到 Actual Cost，沒有其他資料來源可替代。

    3. 下一步建議：找到 Actual Cost 系統負責窗口（任務 8），用本報告的量化證據（逐筆比對＋計畫比對結果）去談，確認是否啟動第一階段的局部整合（建議從 GEM 部門優先，MES 資料可信度最高）。

    成本參數

    依 MES 生產工時與費率計算每個已偵測製程的 Actual Cost；缺少的 Routing 步驟不計為零成本。
